# Trade ERP 业务流程与架构规划 · 总览（00）

> 本文是综合汇总（先总后分）。四个角色分报告在同目录：01 业务需求分析 / 02 业务流程分析 / 03 系统架构分析 / 04 人机交互分析。所有结论均经代码实证（文件:行可查），日期 2026-10-23。

---

## 一、业务本质：两条业务线，两种系统姿态

| | B2B 线（阿里国际站） | 平台零售线（亚马逊 4 站点 / TikTok） |
|---|---|---|
| 履约主体 | 我们自己（询盘→报价→订单→出库→物流→收款） | 平台（FBA/平台仓自动销售发货） |
| ERP 姿态 | **权威源**：单据驱动，主动管理全闭环 | **只读镜像**：销售/平台仓库存只拉不管 |
| ERP 管什么 | 销售订单、出库单（必须关联销售订单）、物流、收款 | 海外仓库存、备货（采购→头程物流→入库→补货）、国内订货、平台数据只读同步 |

平台线的真正业务不是"销售"，而是**备货链**：国内采购 → 头程物流 → 海外仓入库 → 平台仓补货，配合平台销量/库存数据回流做补货决策。

## 二、现状判断（四份分报告的共同结论）

1. B2B 履约主链已通（询盘→报价→订单→出库→物流→收款），物流订单四级审批是全系统最健壮的模块。
2. **备货链只有表结构、没有业务**：`OverseasWarehouse/OverseasInventory/StockMovement` 三个模型在 src 里零引用；`LogisticsOrder` 只有 `salesOrderId` 没有 `purchaseOrderId`；无入库单流程、无备货计划、无在途实体。
3. **平台数据通道已备好但没接线**：SP-API 适配器（订单/FBA库存/Listings 只读）已实现但无调用方；`PlatformOrder` 表无人写入。
4. **一个必须尽快处理的污染点**：现有 order-sync 把平台零售单直接写进 B2B 的 `Order` 表并自动建客户——两类业务混账，且靠 findFirst 去重有重复建单风险。
5. **库存模型是最大地基问题**：`InventoryItem.warehouse` 是裸字符串，cuid / 仓库编码 / 'MAIN' 混用，同一物理仓会分裂成多条库存行；`PlatformSyncConfig` 唯一键 platformCode 卡死"1 平台 1 账号"，亚马逊 4 站点无法并存。
6. UI 层：侧栏按"实体表"组织而非"业务链"，8 个页面不可达（含询盘），缺老板/运营/财务三个角色。

## 三、目标蓝图

三条业务链 + 一个中心：

1. **B2B 销售链**（主动管理）：询盘 → 报价 → 销售订单 → 出库单（强制关联）→ 物流订单（四级审批）→ 收款
2. **备货链**（主动管理）：补货建议 → 采购订单 → 头程物流订单（关联采购单）→ 入库单（部分/全部/拒收）→ 海外仓库存台账
3. **平台数据链**（只读镜像）：平台订单/FBA库存/Listings 定时同步 → 快照表 → 库存水位预警 → 喂给备货链的补货引擎
4. **审批中心**：各业务流独立配置审批人与步骤（沿用四级审批模式）

关键架构决策（详见 03 的 7 条 ADR）：
- 库存统一为 `InventoryBalance`（快照）+ `InventoryLedger`（事件账），仓库位置统一为 Warehouse 外键（废除裸字符串）
- 海外仓库存"本地台账 vs 平台镜像"双账对账：台账是权威，镜像用于校验与差异告警
- 平台镜像快照优先（快照表族 + SyncJob DB 调度抢单），多站点以 marketplaceId 为维度
- 平台零售订单不再写入 B2B Order 表，进入 PlatformOrder 镜像表
- 补货引擎 L1/L2/L3 三级串联公式（安全库存 = z×σ×√LT，可用量 = 在手+在途-已承诺）

## 四、实施路线（三期）

- **P0 修复（先行，不依赖新模型）**：平台单停止污染 B2B Order 表；库存 warehouse 字段归一；出库确认重复计数 bug；收款绕过状态机 bug。
- **第一期 · 备货闭环**：入库单实体+流程、LogisticsOrder 增加 purchaseOrderId 关联、海外仓库存台账（API+页面）、仓库主数据统一。退出标准：一票"采购→物流→入库→台账"全链路真实数据走通。
- **第二期 · 数据回流与补货**：平台镜像快照三表接线 SP-API/TikTok 同步、多站点配置（4 个 marketplace 并存）、镜像↔台账对账页、补货建议引擎+一键转采购/物流单、角色工作台（6 角色待办首屏）。
- **第三期 · 扩展**：英国/德国/阿联酋站点合规差异、平台侧写操作（Listings 调价/上下架，风险最高放最后）、多币种 FxRate 精细化。

## 五、已拍板决策（2026-10-23）

1. ✅ **平台零售单从 B2B Order 表剥离**：进 PlatformOrder 镜像表，B2B 报表口径恢复纯净（P0 修复项）。
2. ✅ **海外仓库存双账权威规则**：本地台账是过程权威（入库/补货/核算以台账为准）；平台镜像定期对账；出现不可调和差异（FBA 丢件、平台既成盘点差异）时以 FBA 实际数为终局结算口径，本地台账开"库存差异调整单"拉平，调整单必须留痕（差异原因：丢件/平台差异/其他）。
3. ✅ **允许无销售订单的出库**：salesOrderId 改为可选，需选"出库类型"（销售出库/样品/赠品/内部领用/调拨），无单出库必须填类型+备注。
4. ✅ **补货参数口径**：安全库存服务水平取 90%（z=1.28）；头程时效按该线路历史物流订单的实际均值计算，无历史数据时以物流方式固定默认值兜底。
5. ✅ **角色清单**：新增 老板 owner（只读决策）/ 运营 ops（平台业务）/ 财务 finance 三角色；现有 sales/purchasing/warehouse 保持不变。
7. ✅ **允许跳过采购直接调拨**：备货链支持"国内仓→海外仓"库存移仓（调拨单），不经采购订单。
6. ✅ **亚马逊 4 站点共用一套 LWA 凭证**：同一主账号一次 self-authorize，ERP 同步配置按 (platformCode, marketplaceId) 复合键区分 4 站点（美区=NA 端点，阿联酋/英/德=EU 端点）；PlatformSyncConfig 唯一键需从 platformCode 改为复合键。

**7 项业务决策全部拍板（2026-10-23），设计阻塞清零。**
